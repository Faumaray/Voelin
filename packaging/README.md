# Packaging

The product is **Voelin**, with the app id `io.github.faumaray.Voelin` (also in
`voelin_platform::{APP_NAME, APP_ID}`). The app id names the desktop file,
metainfo, icon, Flatpak and Android app, and cannot change once published.

| Path | What |
|---|---|
| `linux/` | Desktop file, AppStream metainfo and icon, named by app id; `tsgw.service`, the gateway's systemd unit ([gateway-admin.md](../docs/gateway-admin.md#install)) |
| `flatpak/io.github.faumaray.Voelin.yml` | Flatpak manifest |
| `windows/` | NSIS installer and how to build and sign on Windows ([README](windows/README.md)) |

`scripts/package.sh` builds the packages from these ([docs/building.md](../docs/building.md)):
the app for Linux, Windows and Android, and the gateway `tsgw` for Linux servers
only, as its own package.

Every package also carries `THIRD_PARTY_NOTICES.md` (generated by
`scripts/notices.sh`, see [docs/release.md](../docs/release.md)): Flatpak in
`/app/share/licenses/<app id>/`, the Windows installer next to the executable,
the `.deb` files in `/usr/share/doc/<package>/`, the archives in `share/doc/`.
The app shows the same text in its About page.

## Flatpak

flatpak-builder builds offline, so the crates from `Cargo.lock` are listed as
sources in `flatpak/cargo-sources.json`, generated (not committed) with
[flatpak-cargo-generator](https://github.com/flatpak/flatpak-builder-tools/tree/master/cargo):

```sh
curl -LO https://raw.githubusercontent.com/flatpak/flatpak-builder-tools/master/cargo/flatpak-cargo-generator.py
python3 flatpak-cargo-generator.py Cargo.lock -o packaging/flatpak/cargo-sources.json

flatpak install flathub org.freedesktop.Platform//25.08 org.freedesktop.Sdk//25.08 \
	org.freedesktop.Sdk.Extension.rust-stable//25.08 org.freedesktop.Sdk.Extension.llvm20//25.08
flatpak-builder --user --install --force-clean build-flatpak packaging/flatpak/io.github.faumaray.Voelin.yml
flatpak run io.github.faumaray.Voelin
```

Regenerate `cargo-sources.json` whenever `Cargo.lock` changes. Inside the build
`rust-toolchain.toml` does not apply: the `rust-stable` extension must provide at
least the workspace's `rust-version`. The `llvm20` extension provides libclang for
bindgen (PipeWire bindings); the SDK has everything else the build needs (CMake for
libopus, ALSA, fontconfig, xkbcommon, libvpx, PipeWire). CI builds the bundle in the
`package-flatpak` job of the release workflow ([docs/building.md](../docs/building.md)).

Permissions (`finish-args`): network, Wayland with X11 fallback, DRI, PulseAudio
(microphone and speakers), the PipeWire socket (application audio when streaming),
notifications and the Secret Service. Push-to-talk (GlobalShortcuts) and screen
capture (ScreenCast) go through portals and need no permission.

Desktops match windows to the desktop file (taskbar icon, portal permissions) by
the window's app id on Wayland and its X11 `WM_CLASS` class. The app sets both
to the app id (`slint::set_xdg_app_id`), which is the desktop file's name and
its `StartupWMClass`.
